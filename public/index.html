Base URL & Protocol

All HTTP requests must originate from secure clients using HTTPS. The base URL of the deployment is:

https://spotify-canva.vercel.app

Responses are returned as standard JSON strings using standard gzip/deflate transport compressions.

GET /api/canvas

Retrieve full canvas video objects, matching tracks, art thumbnails, and matching creator vectors by querying a track identifier.

Query Parameters

Parameter Type Required Description
trackId String REQUIRED The 22-character unique Spotify track ID (e.g. 6Uj1ctrBOjOas8xZXGqKk4) or the full Spotify track URI (e.g. spotify:track:6Uj1ctrBOjOas8xZXGqKk4).

Response Schema

Returns an object wrapping a list of canvases with details. The schema structure matches the decoded internal Protobuf representations from Spotify client architectures:

Field Path Type Description
canvasesList Array List containing fetched canvas objects matching queried track records.
canvasesList[].id String Unique hexadecimal Canvas ID.
canvasesList[].canvasUrl String Direct MP4 video URL hosted on Spotify's CDN (canvaz.scdn.co). Perfect for standard video looping.
canvasesList[].trackUri String The matching Spotify track URI resource pointer.
canvasesList[].artist Object Details of the artist matching this track instance.
canvasesList[].artist.artistUri String The artist's Spotify URI pointer.
canvasesList[].artist.artistName String The human-readable name of the creator/artist.
canvasesList[].artist.artistImgUrl String High-resolution profile thumbnail image of the artist.

Error Handling

The API handles invalid states gracefully, communicating failures with semantic HTTP status codes:

Status Code Error Response Common Cause
400 Bad Request {"error": "Missing trackId parameter"} The trackId parameter was omitted in the query strings.
500 Internal Error {"error": "Failed to fetch canvas data"} The backend failed to establish token authentications or retrieve content from Spotify's API. This usually happens if the backend SP_DC token is invalid or expired.

Extracting the sp_dc Session Cookie

Spotify's mobile and web client interfaces use a specialized cookie named sp_dc to authorize high-security connections. The Spotify Canvas API needs this token in its `.env` file to retrieve access tokens dynamically.

a

Open a modern browser and navigate to open.spotify.com.

b

Log in with your normal Spotify account details (either free or premium).

c

Press F12 or right-click and select Inspect to open Developer Tools.

d

Navigate to the Application tab (Chrome/Edge) or Storage tab (Firefox).

e

Expand the Cookies dropdown in the left sidebar and select https://open.spotify.com.

f

Locate the cookie named sp_dc and copy its entire string value (typically starts with a long series of characters). Keep this cookie secret!

Under the Hood: TOTP Handshake

Spotify employs advanced protection schemas, rotating their mobile security handshake tokens using Time-based One-Time Password algorithms. The API is hard-coded to support this challenge-response handshake:

  • The backend fetches an active, encrypted secrets dictionary vector directly from a secure upstream repository updated periodically.
  • Using the decrypted dictionary seeds, the service generates a temporary, 6-digit TOTP validation passcode using the standard SHA-1 algorithm over 30-second cycles.
  • The server queries the internal Spotify endpoint /api/server-time to align local timestamps with Spotify's standard synchronization intervals, mitigating drift.

Securing the OAuth Access Token

Once the local TOTP passcode is generated and synchronized with Spotify's server clock, the API sends a request to the official token exchange portal:

GET https://open.spotify.com/api/token

By appending the synchronized TOTP payload and sending the sp_dc cookie value inside the HTTP headers, Spotify issues a high-level mobile bearer token (accessToken).

The backend stores this token in memory and signs raw binary canvas protobuf envelopes, querying Spotify's CDN cache securely without triggering alarms.
